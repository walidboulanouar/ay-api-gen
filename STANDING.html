What ay-api-gen does

Turns any OpenAPI/Swagger spec into a working MCP server and CLI — in two modes:

  • Runtime mode: ay-api-gen serve <spec> — no codegen, just point and run
  • Generate mode: emits standalone MCP server + CLI files you can customize and deploy
  • Reverse: takes existing MCP tools and generates an OpenAPI 3.0 spec back
  • Auto-detects auth (OAuth2, Bearer, Basic, API Key) and generates .env.example per scheme
  • Auto-registers MCP servers in .claude/settings.local.json
  • Ships with CI/CD (GitHub Actions), Docker, Fly.io deploy configs

Architecture Decisions Worth Knowing

ADR-001 — Two-mode (runtime vs generate)

We support both a zero-friction runtime (serve) and a codegen mode that emits standalone files. Runtime is for fast prototyping; generate is for customization and offline deployment. Most competitors pick one — we picked both because each fails the other use case.

ADR-002 — Zod schemas, not raw JSON Schema

MCP SDK v1.29+ requires Zod. We use z.coerce.number()/z.coerce.boolean() because MCP tool args arrive as strings — without coercion every numeric/boolean param breaks.

ADR-004 — Auto-install deps in output dir

Generated MCP servers import @modelcontextprotocol/sdk and zod. We emit a package.json and run npm install automatically so standalone usage works without manual setup.

ADR-005 — Detect security schemes from spec

We parse securityDefinitions (2.0) and components.securitySchemes (3.x) and generate auth code + .env.example entries specific to each scheme. Users don't have to figure out what auth an API needs.

Known Gotchas (from session handoffs)

  • MCP SDK requires Zod schemas — plain {type: "string"} objects throw. Always z.string(), z.coerce.number(), etc.
  • Template-literal escaping — generators that emit JS containing backticks must use string concatenation + a tpl() helper, not nested template literals.
  • Relative server URLs — OpenAPI 3.x specs like Petstore use /api/v3. Resolve against the source URL origin; parser attaches _sourceUrl for this.
  • Swagger 2.0 body params — they live in the parameters array with in: "body", while OpenAPI 3.x uses requestBody. Parser handles both and filters body params out of the params array.
  • Duplicate tool names — when a spec has duplicate path/method combos, dedupe at codegen time (fixed in commit 0e866b5).
