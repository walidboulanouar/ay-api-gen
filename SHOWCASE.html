② Competitive Gap Analysis

Full sourcing and citations in GAP-ANALYSIS.md. 5 competitors researched via public web only (no signups, no authenticated scraping): Speakeasy/Gram, FastMCP, openapi-mcp-generator, DigitalAPI, cnoe-io/openapi-mcp-codegen.

The headline finding. Two of the five competitors have real, disclosed, patched vulnerabilities in exactly the classes of bug this project hardened against before shipping:
  • FastMCP — CVE-2026-32871 / GHSA-vv7q-7jx5-f767: unencoded path-parameter substitution let ../ escape the intended API prefix — an authenticated SSRF (the forged request still carried the configured auth headers).
  • openapi-mcp-generator — issue #68 (SSRF via uncontrolled external $ref resolution) and issue #67 (template-literal injection via unsanitized description fields that could leak process.env to MCP clients — structurally the identical class to this project's own T-ING-1/T-GEN-1 fixes). Their own SSRF fix regressed within the same week (#70), needing an emergency point release.
This turns "we have SSRF guards and injection-safe codegen" into a citable, factual claim, not a feature-list assertion: two direct competitors shipped exactly these bugs to production; we caught and fixed the same classes with regression tests before ever shipping.

What we already do better (evidence-backed, not just claimed)

  • Minimal dependency footprint — exactly 2 packages (@modelcontextprotocol/sdk, yaml), both exact-pinned, vs. competitors pulling in 4+ packages or a full Python/TS toolchain.
  • The only fully transparent, zero-signup, zero-cost security tool in the category — audit --baseline runs locally, no account, source-available end to end. Every other competitor's pricing is now enterprise-contact-only or behind an auth wall.
  • Reverse generation (MCP tools → OpenAPI) — FastMCP explicitly lacks this (their own open issue #4107).
  • File locking and settings-namespace collision protection — not mentioned in any of the five competitors' docs or source.
  • Full OpenAPI 3.1 handling with real regression coverage — FastMCP's own tracker shows a user-reported breakage on exactly the 3.0/3.1 schema-shape mismatch this project specifically tests for.
