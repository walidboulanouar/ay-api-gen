3Generate the MCP Server

ay-api-gen generate emits a standalone, installable MCP server — Zod-validated tool schemas, auth wiring, and the security guards (SSRF host-checks, description sanitization, response truncation) baked in by default, not bolted on after.

5Security / Audit Output

Before ever generating a server, ay-api-gen audit --baseline statically lints the spec itself — no credentials, no network calls to the target API, free T0 tier. This is the differentiator: most generators skip straight to codegen.

walid@dev — zsh — ay-api-gen audit --baseline
$ ay-api-gen audit --baseline openapi.json ay-api-gen audit --baseline (T0 static analysis, free) API: Acme Billing API (14 endpoints) [spec-lint] 4 finding(s): HIGH T-API-3 POST /customers/{id}/charge request body field "amount_cents" gates monetary value and is not marked readOnly → mark server-computed fields readOnly:true, or validate server-side before charging HIGH T-API-2 GET /customers/{id}/balance path parameter "id" resembles a sensitive/PII identifier → confirm this ID is opaque and not derived from SSN/account-number, or scope access via auth MED T-API-1 DELETE /invoices/{id} mutating endpoint has no per-operation security requirement (relies on global only) → verify the global security scheme actually applies here; declare explicitly if unsure MED T-API-5 * (spec-wide) globally-declared auth scheme is optional (security: [] present alongside bearer) → remove the empty security override unless anonymous access is intentional 0 CRITICAL, 2 HIGH, 2 MEDIUM — mode=a (warn-only), generation not blocked. Re-run with --mode=b to block generation on HIGH/CRITICAL until --accept-risks is set.
HIGHT-API-3 · mass-assignment heuristic
POST /customers/{id}/charge — request body field amount_cents gates monetary value and is not marked readOnly.
→ Mark server-computed fields readOnly: true in the spec, or validate server-side before charging.
HIGHT-API-2 · sensitive path parameter
GET /customers/{id}/balance — path parameter id resembles a sensitive/PII identifier.
→ Confirm this ID is opaque and not derived from SSN/account-number, or scope access via auth.
MEDT-API-1 · unauthenticated mutating endpoint
DELETE /invoices/{id} — mutating endpoint has no per-operation security requirement.
→ Verify the global security scheme actually applies here; declare explicitly if unsure.
Same audit, run in --mode=b (enforced) with an unacknowledged HIGH finding — generation is blocked, not just warned:
